# Vendor Handshake - Vendor Onboarding Platform (VOB)

Public, internet-facing Laravel 12 app. Vendors sign in from an emailed link, fill the Terms of Trade form, upload documents to S3,
verify their bank account with Cashfree and submit. There is **no business database**: all data goes through the Admin Panel REST API
(`docs/API_CONTRACT.md`). Plan and phases: `docs/DEVELOPMENT_PLAN.md`. Working rules: `CLAUDE.md`.

## Status

All five phases are done: Admin API client + logging, sign-in / password flow, the Terms of Trade form (Save Draft, autosave, locked / mandatory fields from the API, document upload to S3), Cashfree bank verification, and Submit / Resubmit with a read-only status page. eMudhra e-sign (Phase 6) and the security review (Phase 7) are not started.

## Setup

```
composer install
cp .env.example .env
php artisan key:generate        # owner runs this
php artisan migrate             # sessions, cache, jobs, api_logs (SQLite by default; set DB_* for MySQL)
vendor/bin/pest                 # needs a .env to exist, otherwise PHPUnit reports every test as a warning
```

## Keys and secrets (owner-created, never committed, never generated by the code)

| Variable | Meaning |
|---|---|
| `ADMIN_API_BASE_URL` | Admin API base incl. prefix, e.g. `https://admin.internal/api/v1` (its path is the signed path) |
| `ADMIN_API_HMAC_SECRET` | same value as `API_HMAC_SECRET` on the Admin side |
| `ADMIN_API_RSA_PUBLIC_KEY_PATH` | `vob_public.pem`, default `storage/app/keys/vob_public.pem` (`*.pem` is git-ignored) |
| `ADMIN_API_RSA_KEY_ID` | key id, e.g. `k1` |
| `ADMIN_API_TIMEOUT`, `ADMIN_API_RETRIES` | seconds / extra attempts for GET, PUT, DELETE (POST is never retried) |
| `API_LOG_RETENTION_MONTHS` | `api_logs` retention, default 2 |
| `VOB_ENFORCE_REQUIRED`, `VOB_ENFORCE_DOCUMENTS` | `false` = Submit not blocked on mandatory fields / documents. Ignored (always on) in production |
| `VOB_SESSION_IDLE_MINUTES` / `VOB_SESSION_ABSOLUTE_MINUTES` | vendor session expiry: no activity for this long (default 30) / since sign-in (default 480). On expiry the vendor sees "Your session has ended" and the invitation link is kept. The Admin token has its own 30 min idle / 8 h limits and ends the session earlier if shorter. Keep `SESSION_LIFETIME` >= the absolute value |
| `VOB_DOCS_DISK` | filesystem disk for vendor PDFs, default `s3` (set `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `AWS_BUCKET`; the bucket must be private and be the same one the Admin reads with `TOT_DOCS_DISK=s3`) |
| `VOB_MASTERS_CACHE_MINUTES` | how long `/masters` dropdown data is cached (default 10) |
| `CASHFREE_ENV`, `CASHFREE_CLIENT_ID`, `CASHFREE_CLIENT_SECRET` | bank verification. `sandbox` needs sandbox credentials, `production` live ones. Whitelist the server egress IP in the Cashfree dashboard |
| `CASHFREE_NAME_MATCH` | `ignore` (default) or `reject_no_match`: the paying account number and IFSC must always match; this also fails a NO_MATCH name |
| `VOB_SKIP_THIRD_PARTY` | **demo / testing only**: `true` skips every third-party service. Bank verification is not sent to Cashfree (the Admin is told `verified` with a `DEMO-...` reference) and documents are stored on the local disk instead of S3. PAN No, GST Regn. No, Account Name, Account No and IFS Code are not validated and always show a green "Verified" (the Admin skips their format checks too while its own `TOT_SKIP_THIRD_PARTY` is on; if it does not, its format error is shown beside the field). A banner shows while it is on. Always off when `APP_ENV=production` |
| `VOB_DISPLAY_TIMEZONE` | timezone for "Draft saved ..." (default `Asia/Kolkata`) |

A missing key/secret/URL raises a clear "not configured" error before any request is sent.

## Scheduler

`logs:purge-api --months=2` runs daily (`routes/console.php`). Cron entry:

```
* * * * * cd /path/to/vob && php artisan schedule:run >> /dev/null 2>&1
```

## Layout

- `app/Services/AdminApi/AdminApiClient.php` - the only gateway to the Admin API: HMAC headers on every call, `X-Auth-Data`
  envelope (AES-256-GCM + RSA-OAEP) with a random decoy body for login / password change, Bearer token from the server-side session,
  retries for idempotent calls (re-signed each attempt), 401 on a Bearer call ends the session.
- `RequestSigner`, `CredentialEnvelope`, `AdminSession` (token + user in the Laravel session only), `ApiLogger`, `ApiLogRedactor`.
- `api_logs` - every outbound attempt; passwords, tokens, emails, `X-Auth-Data`, signatures redacted, account / PAN / GST numbers masked.
- `resources/views/layouts/app.blade.php` + `components/status-tracker.blade.php` - left-margin tracker rendered from the API `progress`.
- `App\Support\EnforcementSwitches` - the two development switches; the layout shows a "Development mode" banner when one is off.

## The TOT form

- `app/Services/Tot/TotLayout.php` = presentation of the reference form (cards, labels, widgets) and the shape of each API section. Locked fields, mandatory fields, dropdown masters and all format rules come from the Admin API on every load; formats are validated by the Admin on each draft save and shown beside the field.
- Save Draft (POST) and autosave (POST, JSON) both call `PUT /tots/{id}/draft`. The TOT id never appears in a URL: it is kept in the server-side session.
- Documents: PDF only, max 5 MB, PDF signature checked, `DocumentScanner` hook for antivirus (no-op by default), stored at `tots/{tot id}/{random}.pdf` in the private bucket, then registered with the Admin; the object is removed again if registration fails.

## Login page for returning vendors (`/login`)

- E-mail + password only, no invitation link: `POST /vendor/login` without `link_token`. The first sign-in from the emailed link (`/onboard/{token}` then `/sign-in`) is unchanged, and a new vendor can also use `/login` with the temporary password.
- After sign-in a temporary password goes to the change-password page first. Then: no Terms of Trade -> "No Terms of Trade yet. Please contact your Lulu buyer."; one -> opened directly; several -> `/tots` (financial year, type, status, editable; newest first), chosen with a POST by list position (never by id). Approved / read-only TOTs open with the tracker and reviewer comments. The header shows "My Terms of Trade" to switch when there are several.
- Failures are one generic message (401, 429, 404 look alike, no hint about which part was wrong); attempts are limited to 10 a minute per IP. When the session ends a vendor who came by link returns to the link sign-in, everyone else to `/login`.

## Terms of Trade clauses (editable by the vendor)

- The 14 clauses are not stored in VOB: their original wording comes from the Admin on every load (`clause_templates`), the vendor's edits are `form.clauses` (`{ key: complete edited text }`, only edited clauses).
- Each title has a pencil icon on the right. It opens the clause as a textarea (original or edited wording, with an extra "Restore original wording" button); closing it after typing saves the draft and reloads. Number fields of clauses 5 and 6 (`{refund_within_days}`, `{min_shelf_life_percent}`) are the `business_terms` inputs, shown in the text and beside the textarea.
- Only opened or already-edited clauses are posted. Empty text or text equal to the original removes the edit at the Admin. Clauses are not mandatory and are read-only once the TOT is not editable.
- The comparison (original struck through in red, new wording on yellow) is shown by the **Admin Panel** to the owner and reviewers; VOB only edits.
- Reviewer "Look for comment" sections (`flagged_sections`, `section_note`): the flagged section titles get a "Comment added" marker and the page scrolls to the first one. Every section card has the Admin's section key as its `id`.

## Bank verification (Cashfree Reverse Penny Drop)

- "Verify bank account" on the form saves the draft, then creates an RPD request for the saved account name / number / IFSC; the vendor pays Rs 1 by UPI (QR or app link, valid 10 minutes, refunded in 48 h).
- The result is read from Cashfree (`GET /remitter/status`), never from a webhook payload. The paying account number and IFSC must match the form; then `POST /tots/{id}/bank-verification` tells the Admin `verified` (with the Cashfree ref_id) or `failed`. An expired link is not reported as failed.
- `cashfree_verifications` is temporary (no account number, only last four digits and a keyed hash); `cashfree:purge-verifications` runs daily.
- Webhook (optional, speeds things up): `POST /webhooks/cashfree`, signature checked, no session. Without it the vendor page polls every 4 seconds, and a payment made while the page was closed is picked up when the form is next opened.

## Submit, resubmit, status

- The Submit button posts the whole form: it is saved first, then the checks the switches allow (Admin `required_fields`, `required_documents`, bank verified or the manual-approval tick), then `POST /tots/{id}/submit`. The Admin repeats every check; its `incomplete` list is shown if it still refuses.
- After submitting, the form is read-only (`tot.editable = false`) with a status card; the tracker stays. If a reviewer sends it back (`pending_vendor`), the comments show, the form is editable and the button reads Resubmit.
- `VOB_ENFORCE_REQUIRED` / `VOB_ENFORCE_DOCUMENTS` = false skip VOB's own checks (the Admin may still refuse); formats are always validated by the Admin. Both are always on in production.

- Every state-changing browser route is POST (a test enforces it). Admin-side changes needed by VOB are listed in `docs/ADMIN_PANEL_CHANGES.md`.
